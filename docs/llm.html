Inteligência Artificial como Instrumento de Medição

Capítulo 5 O LLM como instrumento

Neste capítulo, o LLM entra em cena. Ele não é tratado como um oráculo, mas como um instrumento cujo funcionamento precisa ser descrito com a mesma precisão com que se descreve um questionário: qual modelo, qual pergunta (prompt), quais parâmetros, quais respostas brutas.

5.1 Um modelo brasileiro, aberto e local

Usamos o S5-nano, da Maritaca AI, em modo instruct: um modelo aberto (licença Apache-2.0) de cerca de 4 bilhões de parâmetros. Três características justificam a escolha:

  • É um modelo brasileiro, treinado com dados em português. A Maritaca AI é uma empresa brasileira, e o S5-nano passou por um pré-treinamento adicional com textos em português. As ementas usam o vocabulário do direito e do processo legislativo brasileiros (“tipifica”, “altera o Decreto-Lei nº 2.848”, “Lei das Eleições”), e a fronteira entre PUNIR e REGULAR depende justamente dessas expressões. Um modelo que viu mais texto em português, e sobre o Brasil, tem mais chance de captar essas distinções.
  • Ele vem do Qwen. O S5-nano não foi treinado do zero: ele parte do Qwen3.5-4B, modelo aberto da Alibaba, e herda dele a arquitetura, o tokenizador e boa parte do que “sabe”. O pré-treinamento em português ajusta o modelo-base, mas não apaga o que veio antes. Para quem mede, isso tem duas consequências. Primeiro, a origem faz parte da descrição do instrumento: o S5-nano é um Qwen adaptado ao português, e vieses do modelo-base podem persistir. Segundo, ser brasileiro é uma característica do treinamento, não uma garantia de validade. Ela precisa ser medida na amostra-ouro, como em qualquer outro instrumento (Capítulo 6).
  • É aberto e pequeno. Os pesos são públicos, então qualquer pessoa pode baixar exatamente a mesma versão usada aqui, e o modelo roda numa GPU de notebook, sem custo e sem enviar os dados para fora da máquina.

Rodamos a versão quantizada em 4 bits (formato GGUF, Q4_K_M), publicada pela própria Maritaca. Os pesos ocupam cerca de 2,8 GB, mais 0,7 GB de um módulo de visão que não usamos, e cabem numa GPU de notebook com 6 GB por meio do Ollama. No Ollama, o modelo recebe o nome local s5-nano-instruct, definido num arquivo versionado junto com o material:

ollama pull hf.co/maritaca-ai/S5-nano-GGUF:Q4_K_M
ollama create s5-nano-instruct -f modelos/Modelfile.s5-nano-instruct

A chamada é uma requisição HTTP a um servidor local:

chama_ollama <- function(prompt, modelo, temperatura, semente) {
  msg <- request(file.path(OLLAMA, "api/chat")) |>
    req_body_json(list(
      model = modelo, stream = FALSE, think = FALSE, format = ESQUEMA,
      options = list(temperature = temperatura, seed = semente),
      messages = list(list(role = "user", content = prompt))
    )) |>
    req_timeout(120) |>
    req_perform() |>
    resp_body_json() |>
    pluck("message")
  if (nzchar(msg$thinking %||% "")) stop("o modelo devolveu raciocínio: o modo instruct não foi respeitado")
  msg$content
}

Quatro detalhes dessa chamada e do modelo são decisões de medição:

  • format = ESQUEMA: pedimos saída estruturada, um JSON com os campos categoria (restrita às quatro categorias) e eleitoral (verdadeiro/falso).
  • temperature e seed: com temperatura 0, o modelo escolhe sempre a resposta mais provável; com temperatura maior, há aleatoriedade, controlada pela semente. Os dois parâmetros devem ser sempre registrados.
  • think = FALSE: o S5-nano tem dois modos. No modo think, ele “raciocina” por escrito antes de responder; no modo instruct, responde direto. Usamos só o instruct, porque o think é bem mais lento e produz saídas longas e variáveis. Se a resposta vier com raciocínio, a função para com erro, em vez de registrar em silêncio as respostas de outro instrumento.
  • A quantização: reduzir os pesos a 4 bits torna o modelo viável num notebook, mas o modelo quantizado é outro instrumento. Os resultados que a Maritaca publica foram obtidos com os pesos completos (BF16). O que vale para este material é a validação feita aqui, com o modelo que de fato usamos. O cache também registra o digest dos pesos, porque o nome s5-nano-instruct é só um apelido local.

Por que local? Os dados não saem da máquina, o custo é zero e, principalmente, a versão do modelo não muda sem aviso. Com cerca de 0,41 segundo por ementa numa GPU de notebook, as 304 ementas são anotadas em aproximadamente 2 minutos.

APIs comerciais funcionam da mesma forma, com o pacote ellmer em R ou openai em Python (há exemplos em R/04_anotacao_llm.R e python/03_anotacao_llm.ipynb). Nesse caso, registre o identificador exato do modelo e a data, e guarde as respostas brutas, porque APIs comerciais trocam a versão do modelo sem aviso. A chave de API nunca vai no código: use ~/.Renviron ou variáveis de ambiente.

5.2 O prompt é parte do instrumento

Mudar a redação do prompt é mudar o instrumento. Por isso usamos três versões, versionadas como código (texto completo no Apêndice C):

Tabela 5.1: Versões do prompt.
Versão Conteúdo Motivação
v1 Só os nomes das categorias O que o modelo “entende” sozinho por PUNIR, REGULAR e PROMOVER?
v2 v1 + definições e regras do livro de códigos Aproximar o LLM do codificador humano treinado
v3 v2 + 6 exemplos fictícios (few-shot) Testar se exemplos melhoram as categorias ambíguas

Os exemplos do v3 são fictícios de propósito: usar ementas reais arriscaria vazar casos da amostra-ouro para o modelo, o mesmo problema do dicionário no capítulo anterior.

5.3 Cache: as respostas do LLM são dados

Cada chamada fica registrada em dados/cache_llm/<run_id>.jsonl, uma linha por ementa, com o modelo, o identificador e o hash SHA-256 do prompt, a temperatura, a semente, a resposta bruta, o rótulo extraído, o tempo e a data. Este é o primeiro registro real do cache:

{
  "doc_id": "doc0001",
  "run_id": "s5-nano-instruct__v2__t0.0__s42",
  "modelo": "s5-nano-instruct",
  "modelo_digest": "85ec77c8f04e",
  "ollama_versao": "0.40.15",
  "prompt_id": "v2",
  "prompt_sha": "c4b5a5ade801",
  "temperatura": 0,
  "semente": 42,
  "resposta_bruta": "{\"categoria\": \"REGULAR\", \"eleitoral\": false}",
  "categoria_llm": "REGULAR",
  "eleitoral_llm": false,
  "segundos": 0.451,
  "timestamp": "2026-11-12T02:38:40+00:00"
}

Esse formato resolve três problemas de uma vez:

  1. Auditoria. Qualquer pessoa pode conferir o que o modelo respondeu de fato, e não apenas o rótulo que extraímos.
  2. Retomada. Se o processo for interrompido, ele continua de onde parou; nada é anotado duas vezes. Se uma nova coleta trouxer projetos novos, só eles são enviados ao modelo.
  3. Replicação sem o modelo. Quem não tem GPU nem Ollama refaz todas as análises a partir do cache.

O material traz 6 execuções: os três prompts com temperatura 0 e semente 42, e o prompt v2 com temperatura 0,8 e sementes 1, 2 e 3 (usadas no teste-reteste do próximo capítulo).

5.4 Falhas de formato

Mesmo pedindo saída estruturada, o modelo pode devolver algo fora do formato: o JSON envolvido em blocos de código Markdown (```json ... ```), texto extra ou um campo com outro nome. Por isso a extração do rótulo é deliberadamente tolerante (procura o primeiro objeto JSON na resposta), e as falhas que restam são contadas, nunca descartadas em silêncio. Nas 6 execuções deste material, a taxa de falhas de formato foi 0%. Com outros prompts ou outra versão do Ollama, ela pode não ser zero, e a taxa de falhas é ela própria uma propriedade do instrumento.

5.5 Mão na massa: chamar o modelo, guardar e ler o cache

Como executar

  • Pré-requisito: Ollama instalado e o modelo criado (Apêndice A): ollama pull hf.co/maritaca-ai/S5-nano-GGUF:Q4_K_M e ollama create s5-nano-instruct -f modelos/Modelfile.s5-nano-instruct.
  • Em Python (como os dados do material foram gerados): python python/anotar_llm.py --todas anota o corpus com as 6 configurações (cerca de 15 minutos numa GPU de notebook). Para um teste rápido: python python/anotar_llm.py --prompt v2 --semente 7 --n 5. No Colab: notebook python/03_anotacao_llm.ipynb (com GPU T4).
  • Em R: Rscript R/04_anotacao_llm.R anota as 10 primeiras ementas com o prompt v2 e a semente 7.
  • Atenção: os dois comandos acrescentam registros em dados/cache_llm/. Uma semente diferente de 42 cria um arquivo novo, que as análises dos capítulos seguintes mostram como instrumento à parte. Para não misturar seus testes ao material, use --pasta (Python) ou apague o arquivo de teste depois.
  • Sem GPU e sem Ollama: tudo a partir da seção “Ler o cache” roda só com os arquivos do material.

5.5.2 O prompt e sua impressão digital

Cada prompt é um arquivo em prompts/, com {{ementa}} no lugar do texto a classificar. O hash SHA-256 do arquivo é a “impressão digital” do prompt: se uma vírgula mudar, o hash muda.

# define chama_ollama(), extrai_rotulo() e anota_corpus()
source("R/04_anotacao_llm.R")
for (arq in list.files("prompts", "\\.txt$", full.names = TRUE)) {
  txt <- readChar(arq, file.size(arq), useBytes = TRUE); Encoding(txt) <- "UTF-8"
  sha <- substr(digest(txt, algo = "sha256", serialize = FALSE), 1, 12)
  cat(sprintf("%s  sha = %s  (%d caracteres)\n", basename(arq), sha, nchar(txt)))
}
prompt_v1_simples.txt  sha = 5eb0f92ea13d  (252 caracteres)
prompt_v2_codebook.txt  sha = c4b5a5ade801  (1522 caracteres)
prompt_v3_fewshot.txt  sha = 6fdbfaf1d613  (2485 caracteres)
import anotar_llm as al      # python/anotar_llm.py
for pid, arq in al.PROMPTS.items():

O que está sendo executado. chama_ollama() envia uma requisição HTTP ao servidor local (/api/chat) com o nome do modelo, o prompt já preenchido com a ementa, think = false (modo instruct), o esquema JSON da saída e as opções temperature e seed. O modelo devolve um texto, que deveria ser um JSON como {"categoria": "REGULAR", "eleitoral": false}. anota_corpus()/anota() repete isso para cada ementa: antes de começar, lê o arquivo de cache e pula as ementas já anotadas (retomada); depois de cada resposta, grava uma linha JSON com a resposta bruta, o rótulo extraído e todos os metadados do instrumento. O nome do arquivo (run_id) codifica modelo, prompt, temperatura e semente.
